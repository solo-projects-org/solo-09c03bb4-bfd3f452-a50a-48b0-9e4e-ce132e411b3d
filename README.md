# 保护区鸟类普查名录对照系统

用最新版名录比较历年鸟类普查数据的网页应用：Flask + SQLite，Docker Compose 一键启动。

## 启动

```bash
# Docker（推荐）
docker compose up --build
# 打开 http://localhost:8000

# 本地开发
pip install -r requirements.txt
python3 run.py            # 默认 http://127.0.0.1:8000，PORT 环境变量可改端口
```

SQLite 数据库位置由 `BIRDAPP_DB` 指定（容器内默认 `/data/birdapp.db`，挂在命名卷
`birdapp-data`；本地默认 `./data/birdapp.db`）。首次启动自动建表；已有旧库首次升级时
会在一个事务内按现有明细全量建立分组小计，大库首次启动会多花一点时间。

## 数据格式（UTF-8 CSV）

**普查记录**：`记录号,年份,名录版,学名,只数`
- 记录号唯一；重传按记录号更新。原名/原版不变时只更新年份和只数并保留复核确认；
  原名/原版变更则清除该记录的旧确认。

**名录对照**：`起版,旧学名,下一版学名`
- 每行表示「起版 v → v+1 时，旧学名变为下一版学名」，版号为连续整数。
- 同一（起版, 旧学名）多行 = 拆种；多个旧学名指向同一名称 = 并种；未列出的名称沿用。
- 最新版号 = max（对照最大起版+1, 记录最大版号, 已确认最大版号）。

`samples/` 下有可直接上传的示例：v1→v2 银鸥拆种、v2→v3 又并回（拆种后再并种），
赤嘴潜鸭 v1→v2 拆种，以及一好一坏两份整份替换对照。

## 功能与规则实现

- **分组小计**：明细表之外维护按「换算起点」和年份分组的小计
  （起点 = 已确认则确认学名/确认版，否则原名/原版），以及起点集合、起点版号
  三个辅助表。由数据库触发器在同一事务内随明细增删改同步维护；升级前已存在的
  数据库会在首次启动时用一个事务全量建立小计（`meta.subtotals_version` 记录
  是否已建，之后重启不重复重建）。
- **按年汇总**（/aggregate）：勾选最新版的一组物种。汇总时先把所选物种按对照表
  反向推到各起点版本，得到每个起点版本的「可达集合 R」和「全落组内集合 F」，
  再只读分组小计累加：
  - 起点落在 F → 计入该年「最少」和「最多」；
  - 起点落在 R 但不落在 F（部分命中）→ 只计入「最多」；
  - 不在 R → 不计。
  只有当某个起点组是部分命中时，才按（起点版, 起点学名）逐条读取该组的原记录，
  写入「造成差额的原记录」；计数以记录为单位，同一笔计数即使沿多条路径
  （拆种后再并种）到达组内也只计一次。
- **复核确认**（/records）：为整条记录确认一个学名和版号，系统校验该学名必须
  从原名按当前对照可追到（原版 ≤ 确认版 ≤ 最新版），否则拒绝；确认后汇总从确认版换算。
  可随时清除确认。复核、清除、明细改年均由触发器同步更新移出组与移入组的小计。
- **整份更换对照**（首页上传）：只扫描**已确认**记录，用新对照校验其确认学名/版号
  能否从原名追到；未复核的明细不参与校验。只要有追不到的，页面列出记录号并**保留旧表**；
  全部可追才在一个事务内 DELETE+INSERT 整表替换。更换成功后即使最新版号没变，
  年表也立即按新对照重算；小计与明细都不需要重建或重扫，维护小计不给换表增加明细扫描。
- **单次汇总不混用新旧对照**：每次汇总在一个只读事务内一次性取对照表、起点集合、
  小计与差额记录的快照后再计算，上下界与差额记录取自同一快照。
- **写入失败可回查原结果**：明细与小计的写入在同一事务内提交或回滚；任一写入失败
  都会整批回滚，原有明细、对照和汇总结果保持不变。
- CSV 任何一行校验失败则整份拒绝，不落半截数据。
- 统计口径与 JSON 字段沿用原实现：`POST /aggregate` 加 `format=json` 返回
  `latest_version`、`group`、`years`（`year`/`min`/`max`/`diff_records`）、
  `diff_records`；`GET /api/status` 返回库内统计。

## 已知限制（未完成项）

- 无登录与权限控制，复核操作不记录操作者和时间（无审计日志）。
- 记录复核页一次列出全部记录，未分页；记录很多时该页面仍会全表读取，
  汇总页已不再如此。
- 仅支持 UTF-8 CSV；Excel 直接另存的 GBK 文件需先转码。
- 名录对照只支持整份替换，不提供单条增删界面。
- 小计与明细的同步依赖 SQLite 触发器；绕过本应用直接改库时须保持两者一致
  （或删除 `meta` 中的 `subtotals_version` 触发下次启动重建）。
- 生产部署使用 Flask 内置服务器，高并发场景应换 gunicorn/waitress（镜像未内置）。
